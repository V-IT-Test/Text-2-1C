# Методы улучшения LLM-генерации 1С-запросов: обсуждение и ранжирование

Этот файл фиксирует обсуждение потенциальных модулей пайплайна для магистерской работы
«Преобразование запросов на естественном языке в язык запросов 1С с помощью LLM».
Цель — зафиксировать исходные идеи автора, расширенный список техник из Text-to-SQL
литературы, и ранжирование по сложности реализации в текущем сетапе.

Дата фиксации: 2026-04-23.

---

## 1. Исходный список идей автора (7 подходов)

Автор предложил следующие направления экспериментов:

1. **Правила языка запросов 1С в промпте.** Очевидная техника, не требующая
   отдельного исследования.
2. **Диалог с пользователем** перед генерацией запроса или после неё. Основная
   проблема — как оценивать такой режим на 100+ тестах без участия человека, особенно
   с разными LLM.
3. **Декомпозиция запроса на блоки** по операторам («Группировать», «Агрегация»,
   «Условия ГДЕ» и т.д.) перед генерацией.
4. **Декомпозиция запроса на подзапросы.**
5. **Фоновые разведочные подзапросы** — LLM перед генерацией заглядывает в базу,
   чтобы понять, какие значения принимают столбцы. Автор заметил, что в 1С это
   могут быть перечисления.
6. **Chain-of-Thought** — неясно, включается это на стороне модели или есть
   инструменты.
7. **Агент-критик с циклом пересборки** — мультиагентный подход; автор не знаком
   с этой областью и попросил объяснить.

## 2. Расширенный список (15 техник, отображение в академические названия)

На основе обзоров Text-to-SQL 2024–2025 каждая идея автора получила академический
аналог. Добавлены техники, отсутствовавшие в исходном списке.

| # | Техника автора | Академическое название | Ключевые источники |
|---|----------------|------------------------|---------------------|
| 1 | Правила в промпте | Prompt engineering / rule injection | baseline |
| 2 | Диалог с пользователем | Interactive / multi-turn Text-to-SQL | Bird-Interact (arXiv 2510.05318) |
| 3 | Разделение по операторам | DIN-SQL (four-stage) | Pourreza & Rafiei, NeurIPS 2023 |
| 4 | Декомпозиция на подзапросы | QDecomp / Least-to-Most | Zhou et al. |
| 5 | Фоновое исследование значений | Value-based schema linking / DB content retrieval | BRIDGE, CHESS |
| 6 | Chain-of-Thought | Prompt-based CoT либо reasoning models (o1, R1) | Wei et al. 2022 |
| 7 | Агент-критик | Self-Refine / Reflexion / MAC-SQL Refiner | Madaan et al., Wang et al. 2024 |

Добавленные мной техники:

| # | Название | Суть |
|---|----------|------|
| 8 | Execution feedback loop | Вернуть текст ошибки 1С в LLM и перегенерировать; ядро Refiner в MAC-SQL |
| 9 | Few-shot retrieval (DAIL-SQL) | Банк пар `(NL, 1С-запрос)` + retrieval top-K по эмбеддингам |
| 10 | Schema linking отдельным шагом | Доп. LLM-вызов «какие объекты схемы нужны?», фильтрация schema.md |
| 11 | Self-consistency / voting | N запросов при `temperature>0`, выполнить все, проголосовать по результату |
| 12 | Grammar-constrained decoding (PICARD) | Форсировать валидные токены по EBNF-грамматике |
| 13 | Query plan как промежуточное представление | Сначала план на естественном языке, затем запрос по плану |
| 14 | Fine-tuning небольшой модели | ИСКЛЮЧЕНО автором (нет ресурсов/времени/датасета) |
| 15 | Hybrid: rules + LLM | Шаблоны для частотных запросов, LLM как fallback |

## 3. Оценка сложности реализации в текущем сетапе

Сетап:
- Streamlit UI + OpenAI-compatible API через proxyapi.ru
- 1С COM bridge (32-bit venv), экспорт XMLConfiguration, компактная `schema.md`
- Небольшая тестовая база с 3 документами, 3 справочниками, 1 регистром сведений

### 🟢 Очень просто (несколько часов)

**1. Правила 1С в промпте.** Правка system prompt в
[pipeline/query_translator.py](../pipeline/query_translator.py). Добавить свод правил:
только язык запросов, `ВЫБРАТЬ`/`ИЗ`/`ГДЕ`, `ЗНАЧЕНИЕ(Перечисление.X.Y)` для enum-фильтров,
`.Ссылка` у документов, `СрезПоследних()` для периодических регистров и т.д.
Без новых зависимостей.

**2. Chain-of-Thought.** Одна строка в промпте: «Сначала рассуждай пошагово, потом
выдай запрос в блоке ```». Опциональный парсер, отделяющий рассуждение от финального
запроса. Альтернатива — reasoning-модели (o1, DeepSeek-R1), где CoT встроен,
переключение через выбор модели.

**3. Query plan как промежуточное представление.** Промпт в два хода: сначала
«составь план на русском (какие таблицы, срезы, фильтры, группировки)», потом
«собери по плану 1С-запрос». По сложности ~= CoT, но с явным структурированным шагом.

**4. Execution feedback loop.** Обёртка вокруг существующего `execute()`:
ошибка 1С → текст ошибки обратно в LLM → перегенерация. Цикл с лимитом 2–3 итерации.
Код в одном файле. Почти бесплатно в реализации, сильный прирост качества.

### 🟡 Просто (день-два)

**5. Schema linking отдельным шагом.** Перед генерацией доп. LLM-вызов
«какие объекты схемы нужны для этого запроса?», парсим ответ, отдаём в основной
промпт только эти куски `schema.md`. Полезно, когда база разрастётся (сотни объектов).

**6. Value-based schema linking.** Расширить `schema_compiler2.py`: для каждого
справочника выполнить `ВЫБРАТЬ РАЗЛИЧНЫЕ ТОП 20 Наименование ИЗ …`, добавить в
`schema.md` как «примеры значений». Перечисления уже выводятся полным списком.
Одноразовый предпроцессинг при экспорте XML.

**7. Few-shot retrieval (DAIL-SQL).** Собрать банк пар `(NL, 1С-запрос)`
(50–100 штук руками), посчитать эмбеддинги (`sentence-transformers` или OpenAI
`embeddings`), на запрос выбирать top-K похожих, вставлять в промпт как few-shot.
Основная работа — собрать банк.

### 🟠 Средне (несколько дней)

**8. Multi-agent Self-Refine / Critic.** Добавить «агента-критика»: после генерации —
отдельный промпт «найди ошибки в этом запросе относительно схемы и намерения
пользователя», критика → перегенерация. Несколько связанных вызовов, оркестрация
в Python (без LangGraph/AutoGen — ручной цикл проще).

**9. Self-consistency / voting.** Генерируем N запросов с `temperature=0.7`,
**выполняем все в 1С**, группируем по результату, возвращаем самый частый.
Нетривиально: два разных запроса могут возвращать одинаковые строки — нужна
нормализация результата для сравнения (хэш отсортированных строк).

**10. DIN-SQL декомпозиция (4 стадии).** Пайплайн: schema linking →
классификация сложности запроса (Easy/Nested/Join) → генерация по шаблону
соответствующей сложности → self-correction. Много промптов + state machine,
но каждый шаг сам по себе прост.

**11. QDecomp — декомпозиция на подзапросы.** Сложнее DIN-SQL: нужно корректно
*собрать* подзапросы обратно в валидный 1С-запрос, а это не всегда механически
возможно (например, `СрезПоследних()` не вложить в другую виртуальную таблицу).
Требует аккуратных правил склейки.

**12. Hybrid rules + LLM.** Шаблонный матчер (регулярки / ключевые слова) для
топ-10 частотных запросов («остатки по складу», «принятые в году»), LLM как
fallback. Много инженерной работы, научная ценность средняя.

### 🔴 Сложно (неделя и больше)

**13. Clarification + LLM user simulator.** Два цикла:
- *Production loop*: основная LLM задаёт уточняющие вопросы → пользователь отвечает →
  итерация до готового запроса.
- *Evaluation loop*: симулятор-пользователь (другая LLM с доступом к ground truth,
  с ограниченным протоколом ответов а-ля Bird-Interact: `AMB() / LOC() / UNA()`),
  прогоняющий все тесты.

Нужен датасет с ground truth. Самая тяжёлая инженерия по объёму работы, но научно —
топ-кандидат (попадает в свежий research gap).

**14. Grammar-constrained decoding (PICARD-style).** В текущем сетапе практически
нереализуемо:
- OpenAI-compatible API через proxyapi.ru поддерживает только JSON Schema
  (Structured Outputs), не произвольную EBNF-грамматику.
- Полноценный constrained decoding (outlines, guidance, SGLang, llama.cpp grammars)
  работает только с локальной моделью и доступом к логитам/токенизатору.
- Для 1С-языка запросов нет готового парсера/грамматики — пришлось бы писать самой.

Реалистичный суррогат — **post-hoc parser** + retry при синтаксической ошибке,
но это фактически упрощённый #4, а не constrained decoding.

## 6. Research gap для магистерской

Text-to-SQL исследован глубоко, но **Text-to-1C — практически нет** публикаций.
Ожидаемый вклад работы:

1. Русскоязычный domain-specific benchmark (аналог Spider/BIRD для 1С).
2. Адаптация DIN-SQL / MAC-SQL на язык запросов 1С с замером качества.
3. Особенности 1С, отсутствующие в SQL: срезы последних/первых, виртуальные таблицы
   регистров, перечисления с синонимами, двойные имена (технические + русские).
4. Interactive setting для доменных экспертов: бухгалтеры/учётчики не пишут SQL,
   но могут отвечать на уточняющие вопросы — особенно релевантно для 1С.
