# Schema v1 — Компактный Markdown из XMLConfiguration

**Дата:** 2026-04-23  
**Файл:** `pipeline/schema_compiler2.py`  
**Формат вывода:** Markdown, ~3 КБ для тестовой БД

## Алгоритм

Источник данных: папка `XMLConfiguration/`, сгенерированная командой
`1cv8c.exe CONFIG /F<path> /DumpConfigToFiles`.

Для каждого типа объектов (Documents, Catalogs, InformationRegisters,
AccumulationRegisters, Enums) читаются все `.xml`-файлы из соответствующей
подпапки. Из каждого файла извлекается:

1. **Имя** (`Properties/Name`) и **синоним** (`Properties/Synonym`, ru) —
   оба включаются в заголовок: `Справочник.Контрагенты (Контрагенты)`.
2. **Стандартные реквизиты** — прописаны статически по типу объекта
   (например, для Документа: `Ссылка, Номер, Дата, Проведен, ПометкаУдаления`).
3. **Пользовательские реквизиты** (`ChildObjects/Attribute`) —
   имя + синоним + тип.
4. **Для регистров** — отдельно `Dimension` (измерения), `Resource` (ресурсы),
   `Attribute` (реквизиты). Периодичность (`InformationRegisterPeriodicity`)
   выводится текстом, а если регистр периодический — добавляется строка
   `Виртуальные таблицы: СрезПоследних, СрезПервых`.
5. **Для документов** — табличные части (`TabularSection`) с их реквизитами.
6. **Для перечислений** — все значения (`EnumValue`) с синонимами.

### Маппинг типов

| XML-тип | В схеме |
|---|---|
| `cfg:CatalogRef.X` | `Справочник.X` |
| `cfg:DocumentRef.X` | `Документ.X` |
| `cfg:EnumRef.X` | `Перечисление.X` |
| `xs:decimal` | `Число` |
| `xs:string` / `v8:String` | `Строка` |
| `xs:boolean` / `v8:Boolean` | `Булево` |
| `xs:date` / `v8:Date` | `Дата` |

## Пример вывода

```
РегистрСведений.ЦеныНоменклатуры (Цены номенклатуры)
  Периодичность: позиция регистратора
  Измерения: Номенклатура: Справочник.Номенклатура; ТипЦены (Тип цены): Справочник.ТипыЦен
  Ресурсы: Цена: Число
  Реквизиты: Ответственный: Справочник.Пользователи
  Виртуальные таблицы: СрезПоследних, СрезПервых

Перечисление.ВидыКонтрагентов (Виды контрагентов)
  Значения: ЧастноеЛицо (Частное лицо), Организация
```

## Что даёт LLM

- Синонимы позволяют сопоставлять слова пользователя с именами объектов.
- Разделение измерений/ресурсов помогает правильно строить условия фильтрации.
- Значения перечислений позволяют писать корректные `ГДЕ ... = Перечисление.X.Y`.
- Виртуальные таблицы регистров позволяют использовать `СрезПоследних(...)`.

## Известные ограничения

- `ChartOfCharacteristicTypesRef.X` не конвертируется в русское название.
- Регистры накопления: тип регистра (остатки/обороты) читается из `RegisterType`,
  но поле может отсутствовать в некоторых конфигурациях.
- Не извлекаются: константы, планы счетов, бизнес-процессы, задачи, роли.
- Не включаются предопределённые элементы справочников и перечислений
  (те, что созданы в конфигураторе, а не пользователем).
